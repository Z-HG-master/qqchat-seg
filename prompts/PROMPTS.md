## ① 0.5 图片标注（9B 视觉，`s0_media.py`）

- `max_tokens=200`，目标 45–55 字
- 占位符：`{desc}` 写入消息正文为 `[图片：{desc}]`

```
这是一张社交群聊里的图片。判断它属于什么种类的图片，并用 50 字左右（45–55 字）客观描述画面内容。
描述要写清：画面主体/人物/场景、图上出现的文字原文、关键数字与数值、界面或场景在做什么事、这张图在群里可能想表达什么。
只输出一行
```

## ③ 0.6 连发块合并（9B，`s0_merge_runs.py`）

- 输入是同一人的连续发言，带序号
- `{lines}` = 形如 `1. 正文` 的编号列表
- 输出分割区间，如 `1-2,3,4-5`

```
下面是同一个人的连续发言（带序号）。判断这些发言能分成几个语义块（每块内部语义关联性强，主题统一；不得漏行、不得重叠）。
只输出分割区间，格式如：1-2,3,4-5
不要解释。

{lines}
```

## ④ 0.7 @/reply 相关性初审（9B，`s0_at_prep.py`）

- `max_tokens=10`
- `{a}` = 被 @/回复的人此前说的一条消息（截断 300 字）
- `{b}` = 现在这条 @ /回复了 TA 的消息（截断 300 字）
- 只输出 `YES` / `NO`；判 YES 才建立链接

```
你在处理社交群聊记录相关性判别。下面是【被@/回复的人此前说的一条消息】和【现在这条 @ /回复了 TA 的消息】。
判断【现在这条】是否在与 TA 此前的消息存在关联性。

【TA 此前说】
{a}

【现在这条】
{b}

判「YES」的情况：
- 【现在这条】消息在回应 / 追问 / 补充【TA 此前说】消息里的人、事、物，图时
- 【现在这条】消息为短反应（"？""确实""草""哈哈哈"等等）且能看出是在回应上面【TA 此前说】的消息、或是对【TA 此前说】的消息内容的吐槽（包括反讽、比喻和阴阳怪气等等）或表达情绪时（感慨，赞叹，附和等等）
- 【现在这条】消息是由【TA 此前说】的消息中延续出的具有相关性的话题
- 【现在这条】消息发的图或表情，能看出是接着【TA 此前说】的消息或对【TA 此前说】的消息表示情感吐槽和回应的（例如回应前面的截图，补充同一件事的画面，用图片表达自己对前消息的情绪感慨、认同、附和、吐槽等）

判「NO」的情况：
- 【现在这条】消息内容（图、文）转向讨论了另一件相关性弱的事时：换了话题、换了对象等等
- 【现在这条】消息内容不满足判「YES」情况中任何一条的要求时

只输出 YES 或 NO，不要解释。
```

## ⑤ 1.1 事件判别 · 逐条 + 外延 5 段（9B，`s1_segment_unit.py`）★

- 默认 `max_tokens=120`（带解释模式）
- `{context}` = 当前事件已认领消息的原文（按时间序，≤4,000 字）
- `{unit}` = 候选消息原文（含 `显示名:` 前缀）
- 下方为 **`--explain` 版**（流水线默认启用）；不带 `--explain` 时末段替换为「只输出一个字：续 或 新」

```
你在处理社交群聊记录的事件归类工作。

【当前对话】下面是这个事件相关的消息记录（按时间先后）：
{context}

【新的一条消息】
{unit}

请判断：这条新消息是不是与【当前话题】里所写对话中谈论的事件/主题有关联？

判「续」的情况：
- 新消息在回应 / 追问 / 补充前文某条消息里的人、事、物，图时
- 新消息为短反应（"？""确实""草""哈哈哈"等等）且能看出是在回应上面某句、或是对前消息内容的吐槽（包括反讽、比喻和阴阳怪气等等）或表达情绪时（感慨，赞叹，附和等等）
- 新消息是由当前话题中延续出的具有相关性的话题
- 新消息发的图或表情，能看出是接着上面的话题或对当前话题表示情感吐槽和回应的（例如回应前面的截图，补充同一件事的画面，用图片表达自己对当前话题的情绪感慨、认同、附和、吐槽等）

判「新」的情况：
- 新消息内容（图、文）转向讨论了另一件相关性弱的事时：换了话题、换了对象等等
- 新消息内容不满足判「续」情况中任何一条的要求时

只输出两行，不要输出其他内容：
判定: 续 或 新
理由: <一句话说明为什么>
```

## ⑥ 1.3 长事件复核（27B，`s1_review.py`）★

- `max_tokens=400`，只对 >10 条的事件触发
- `{lines}` = 形如 `1. 显示名: 正文` 的编号列表
- 输出三行：`结论` / `转折` / `理由`
- **代码护栏**：转折点 `≤1` 或 `≥N` 视为无效；一条中多处转折只取最靠前的；递归深度上限 3

```
下面是社交群聊里一段连续的消息（按时间编号）：

{lines}

请判断：这段对话是不是一段**逻辑顺畅具有强关联性**的、适合作为 llm 训练输入数据源的对话？

注意区分两种情况：
- 顺畅：话题在自然推进，每一段前消息间具有内容主题关联性
- 有转折：出现前后文间的话题切换，转移到一件**关联性弱**的新主题上，或前后文关注话题跨度过大

如果你认为应该切分，请说明：
- 从第几条开始是新话题？
- 为什么这里算话题切换（前后文说的对象/事件有什么不同）？

如果你认为不应该切分，请说明：
- 这段里所有消息的通用主题是什么？
- 如果存在话题重点的转移，那么为什么你认为这段消息仍然是同一件事的延续？

只输出三行：
结论: 顺畅 或 有转折
转折: <编号，或"无">
理由: <两句话说明>
```

## ⑦ 2.1 图片结合上下文重识别（27B 视觉，`s2_media_context.py`）★

- `max_tokens=300`
- `{k}` = 目标图所在消息的序号
- `{ctx}` = 事件全文；目标图位置替换为 `【本次图片】`，其余媒体保留阶段 0 的描述
- 输出两行：`描述` / `关联`；**只有「描述」会回填进数据集，「关联」仅存档**

```
下面是社交群聊里的一段对话（按时间先后编号）。其中第 {k} 条消息带了一张图片（随本消息发送）。

【对话上下文】
{ctx}

请结合上下文描述这张图片。

要求：
- 「描述」以一句话连贯描述，输出内容不超过80字
- 「描述」需要尽可能包含以下三类信息：① 图片的类型与场景（结合上下文判断）② 发言人想通过它表达的信息（观点、吐槽或情绪）或发送这张图片的用意 ③ 图片画面上出现的、与这段对话内容有关的文字与数字
- 「描述」输出内容仅涉及图片文件内相关推理内容，禁止涉及发言人、回复人及具体的上下文信息等相关信息
- 「关联」另起一句，说明这张图片与上面这段对话之间的联系
- 合计只输出两行，不要其他内容：
描述: <不超过 80 字>
关联: <一句话>
```

## 不调用模型的步骤

| 步骤 | 脚本 | 做什么 |
|---|---|---|
| 0.1 导入 | `s0_import.py` | 读用户已导出的 `messages.jsonl`，规范化字段（**不做任何数据库读取/解密**） |
| 0.8 收尾 | `s0_finalize.py` | 文本卫生、悬空链接修正 |
| 1.2 链接合并 | `s1_link_merge.py` | 按已确认的 @/reply 链接做非连续合并（并查集 + 规模上限 ≤20 条 / ≤2000 字，超限跳过而非截断） |
| 1.4 质量闸门 | `s1_quality_gate.py` | 丢弃单条事件；丢弃文字含量 <30 的事件（媒体按 15 字计） |
| 1.5 导出 | `s1_finalize_dataset.py` | 事件级导出与规则分类 |
| 2.2 回填 | `s2_build_segments.py` | 用上下文描述替换占位符，生成纯文本连续片段 |
| 2.3 交错导出 | `s2_export_interleaved.py` | 导出图文交错格式（text/image 混合块），供多模态微调 |

## 统一调用参数

| 参数 | 值 | 说明 |
|---|---|---|
| `temperature` | 0.1（判别）/ 0.0（基准测试） | — |
| 思考模式 | **不开启** | 本项目不依赖 reasoning/thinking；需要模型「多想一步」时用提示词要求它输出一句理由（见 1.1 的 explain 尾巴）。部分模型可用 `reasoning_effort` 显式关闭，默认不发送 |
