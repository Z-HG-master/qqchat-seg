# 踩坑记录（换群 / 换模型前必读）

这些是开发过程中真实踩过的坑，写下来是为了让后来者少走弯路。
其中一部分坑来自“数据导出”阶段，本仓库**不包含**任何数据库读取/解密工具，
这里只保留现象与结论，供你导出数据时参考。

## 数据导入与阶段 0

| 坑 | 现象 | 解法 |
|---|---|---|
| **0 字节空壳文件** | 约 9.4% 的图片 md5 能查到文件、但文件内容是空的 | 索引时跳过 `size == 0`，按“丢失”处理（0.5 里无描述的媒体占位会被移除） |
| **一条消息多张图** | 全部被标成“本次图片” | 按占位符出现顺序逐个编号，只标目标那一张（见 `core/ph_render.py`） |
| **媒体描述含 `]`** | 描述里出现 `"哇我上电视了[天哪]"` 时，简单正则截断、留残渣 | 用括号深度解析器 `ph_render.parse_placeholders`，不要用 `[^\]]*` |
| **JSON 文件带 BOM** | `json.load` 报 `Unexpected UTF-8 BOM` | 读配置/数据统一用 `encoding='utf-8-sig'` |
| **同人连发合并后过长** | 一人连发 20 条被合成一条超长 unit | 0.6 只做“语义分块”，不做条数拼接；分块结果不合法时回退成整块 |
| **时间戳重复** | 同一秒多条消息顺序错乱 | 0.1 用稳定排序（保持导出文件原始顺序），不按时间戳之外的字段重排 |

## 阶段 1（事件切分）

| 坑 | 现象 | 解法 |
|---|---|---|
| **逐条判定的 OUT 是“免费”的** | 收紧提示词后模型对什么都判新，单条率飙到 58% | 不要靠收紧提示词，靠“带解释 + 外延 5 + 复核 + 闸门”组合 |
| **上下文越长越容易判“续”** | 续率随上下文从 23% 涨到 84% | 用固定外延窗口/字数上限，不要让上下文随事件无界增长 |
| **reply 硬捷径会错并** | 24% 的“回复紧邻上一条”其实换了话题 | 取消盲捷径，先做 0.7 语义初审 |
| **并查集合并会传递闭包** | 一条回复链把 722 条 unit 焊成一坨 | 合并时加规模上限（≤20 条 / ≤2000 字），**超限跳过而不是截断** |
| **复核后新产生单条** | 闸门放在复核前会漏 | 闸门统一放最后 |
| **复核可能降分** | 基础切分已经较好时，1.3 复核反而降低 F1（IRC 0.870→0.833） | 把它当可选的“长尾处理”，主切分好时可以跳过 1.3 |

## 阶段 2（图片重述）

| 坑 | 现象 | 解法 |
|---|---|---|
| **单行描述被上下文污染** | 描述里出现“配合某某的调侃”，污染率 15–30% | 拆成「描述」+「关联」两行，描述只讲图 |
| **描述里带发言人名字** | 下游训练文本泄露昵称 | 提示词里明确禁止；解析后 `描述` 与 `关联` 分开存 |
| **模型没按格式输出** | 拿不到 `描述:` 行 | 退化为取第一行（`s2_media_context.py` 已有兜底） |
| **视觉模型不可用** | 换了一个非视觉模型，脚本崩 | `config.json` 的 `model_supports_vision` 开关：关闭时 0.5 / 2.1 自动降级跳过 |

## 工程层

| 坑 | 现象 | 解法 |
|---|---|---|
| **绝对路径硬编码** | 换台机器全挂 | 所有路径来自 `config.json`，相对路径按配置文件所在目录解析 |
| **Windows 中文输出乱码** | 重定向到文件后是乱码 | 统一 `sys.stdout.reconfigure(encoding='utf-8')`，pipeline 子进程设 `PYTHONIOENCODING=utf-8` |
| **静默失败** | 某步没产出文件但流程继续 | 每步都有 `EXPECT` 产物校验（`pipeline.py`），缺失即中断 |
| **断点续跑误判** | 两个步骤共用同一个产物名，导致后一步被跳过 | 每步校验的产物文件各不相同（例如 0.7 校验 `units_at.jsonl`、0.8 校验 `units_stats.json`） |
| **模型不存在时静默产出垃圾** | 端点返回空回复，流程照跑 | `core/llm.py` 区分“传输失败/模型不存在”（抛可读异常）与“空回复”，启动前先 `--check-llm` |

## 关于 `prompts/PROMPTS.md` 与代码内联提示词

`prompts/PROMPTS.md` 是**从代码自动生成**的提示词存档：用 Python `ast` 解析各阶段脚本，
提取实际运行时使用的提示词字符串，再拼装成 Markdown。因此它与代码**逐字一致**（7/7 代码块）。

维护规则：

1. **改提示词只改代码**，然后重新生成 `PROMPTS.md`；不要直接手改 Markdown。
2. 若发现两者不一致，以**代码为准**。

> 历史背景（已解决）：迁移前，存档文档中 0.7 与 1.3 两条是早期压缩版，而代码里是后续迭代的
> 完整版，造成文档与实现不一致。迁移时已按上述方式重新生成，差异已消除。

### 11. Windows 上 print ✓ / ✗ 会 UnicodeEncodeError

Windows 控制台/管道默认编码是 cp1252（英文系统）或 cp936（中文系统），
打印 `✓`(U+2713)、`✗`(U+2717)、`→` 这类符号会直接抛：

```
UnicodeEncodeError: 'charmap' codec can't encode character '\u2713'
```

**这不是编码写错了，而是 stdout 承载不了这些字符。** 修法是显式重配：

```python
for stream in (sys.stdout, sys.stderr):
    try:
        stream.reconfigure(encoding='utf-8', errors='replace')
    except (AttributeError, ValueError):
        pass
```

这个坑只有 CI 的 `windows-latest` 能替你抓到——本地开发终端通常已经是 UTF-8。
`tests/test_smoke.py` 顶部就做了这个重配。

### 12. 推送 `.github/workflows/` 需要额外的 `workflow` scope

即使 token 有 `repo` 权限，`git push` 含 workflow 文件时仍会被拒绝：

```
! [remote rejected] main -> main (refusing to allow an OAuth App to
  create or update workflow `.github/workflows/ci.yml` without `workflow` scope)
```

这是 GitHub 的安全机制（workflow 能执行任意代码）。⚠️ 这一点对**历史重写**同样适用：
force-push 一个包含 CI 文件的提交也需要该 scope。
需要重新授权（`gh auth refresh -s workflow`）或使用带 `workflow` 权限的 fine-grained PAT。

### 13. `ubuntu-latest` 会悄悄升级大版本

2026-10-19 `ubuntu-latest` 从 Ubuntu 24.04 迁到 26.04，**该镜像不再提供 Python 3.9**，
`setup-python` 直接报 `The version '3.9' was not found for Ubuntu 26.04`。

对策：CI 矩阵里不要用太老的小版本；需要老 Python 就显式钉 `ubuntu-22.04`。
另外 Python 3.9 已于 2025-10 结束安全支持，本项目要求 3.10+。

### 14. 某些模型默认开思考模式，单次调用会慢一个数量级

以 Qwen 为例：**不传 `reasoning_effort` 就是开启思考模式**。实测小模型单次 20–32 秒
且经常被截断，大模型对长上下文会写 5,000+ 字推理。

这不是接口协议的一部分，而是模型家族的私有行为。**本项目不依赖思考模式**：
默认配置不发送该字段；需要模型「多想一步」时，用的是提示词层面的
「判定 + 一句理由」（见 1.1），成本只有几十个输出 token。

如果确实很慢：在 config.json 里显式设 `"reasoning_effort": "none"`（可选字段），
或者直接在你自己的推理服务里关掉思考模式。
